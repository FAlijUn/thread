## 基于锁的并发数据结构设计

并发数据结构色设计，多个线程可以并发的访问这个数据结构
使用互斥量提供互斥特性
在互斥量的保护下，同一时间内只有一个线程可以获取互斥锁
序列化：线程轮流访问被保护的数据

* 确保无线程能够看到，数据结构的“不变量”破坏时的状态
* 会引起条件竞争的接口，提供完整的操作函数，不是操作步骤
* 数据结构的行为是否会产生异常，从而确保“不变量”的状态稳定
* 将死锁的概率降低，使用数据的时候，需要限制锁的范围，避免嵌套锁

用户在使用的时候不能在构造函数完成之前和析构函数完成之后对于数据结构进行访问
* 锁的范围中的操作，是否运行在外执行
* 数据结构不同的区域，是否能够被不同的互斥量所保护
* 所有的操作都需要同级互斥量保护
* 能不能对于数据结构进行简单的修改，以增加并发访问的概念

## 无锁并发数据结构设计
使用互斥量，条件量，以及期望来同步阻塞数据的算法和数据结构， 应用调用库函数，挂起一个执行线程,直到其他线程完成某个特定的动作 会产生阻塞
不使用阻塞，无阻塞结构(nonblocking)，无锁lock-free
无阻塞结构并不是无锁的

无锁数据结构
* 线程可以并发的访问这个数据结构
* 线程不能做相同的操作，一个无锁队列可能允许一个线程进行压入数据，另一个线程弹出数据，同时添加数据时数据结构被破坏
* 具有“比较交换”的数据结构，在“比较/交换”(当有其他线程对于指定数据进行更改代码尝试恢复数据)中实现一个循环执行成功程序是无锁的，执行失败需要一个自旋锁“无阻塞有锁”
* 无锁算法的循环会让一些线程饥饿

无锁无等待数据结构
* 每个线程能够在有限的步数之内完成
* 无锁结构要保证每一个线程都能够在有限的步骤里面完成，保证每一个操作可以被一次性执行完成，当线程执行到某一个操作的时候不会让其他线程失败
* 当一个线程在获取锁的时候被杀死，数据结构会被永久性破坏，在无锁数据结构上执行，执行到一半死亡，数据的数据没有丢失，其他线程可以正常执行
